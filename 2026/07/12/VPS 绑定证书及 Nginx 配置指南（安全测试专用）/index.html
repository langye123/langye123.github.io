配置要点解析：

  1. **location /.well-known/acme-challenge/**：这是关键。Certbot 续期时会访问此路径，显式声明可防止 Certbot 在续期时因找不到跳转规则而强制添加 return 301。
  2. **无 return 301**：80 端口 server 块中不包含跳转指令，满足安全测试对 HTTP 明文流量的需求。
  3. **log_format test_access**：包含 $http_cookie，便于在日志中直接分析会话状态。

7. 后续维护

  • 自动续期：Certbot 安装时已自动配置 Systemd Timer 或 Cron 任务，无需手动干预。
  • 验证状态：
    • HTTP: curl -I http://baidu.langye.top (应返回 200，非 301)
    • HTTPS: curl -I https://baidu.langye.top (应返回 200，SSL 握手成功)
  • 日志检查：
    • HTTP 日志：tail -f /var/log/nginx/baidu.langye.top_http.log
    • HTTPS 日志：tail -f /var/log/nginx/baidu.langye.top_https.log

手动触发续期与测试
模拟续期（Dry Run）：在真正续期前，强烈建议先运行此命令进行测试。它会模拟续期过程但不会实际保存证书，用于检查配置是否正确。

sudo certbot renew --dry-run

强制续期：用于调试或紧急场景（正常情况不建议使用，因为证书还有较长有效期）。

sudo certbot renew --force-renewal

强制重启一下

sudo systemctl reload nginx

启动自动更新脚本证书

  1. 证书与账户管理
    查看所有证书状态：查看当前服务器上所有由 Certbot 管理的证书信息，包括到期时间、存储路径和关联的域名。

sudo certbot certificates

  1. 排查与日志监控
    查看 Certbot 运行日志：如果续期失败或报错，可以查看此日志定位问题。

tail -f /var/log/letsencrypt/letsencrypt.log

查看 Nginx 错误日志：如果证书更新了但浏览器仍提示不安全，检查 Nginx 是否成功加载。

tail -f /var/log/nginx/error.log

  1. 验证证书是否生效
    使用 OpenSSL 检查：直接在服务器上验证 443 端口返回的证书链和有效期。

openssl s_client -connect baidu.langye.top:443 -servername baidu.langye.top

查看当前自动申请证书的状态

systemctl status certbot-renew.timer

如果上面是关闭，就开启一下 设置开机自启动，和立即启动

systemctl enable --now certbot-renew.timer
