十一、踩坑记录与问题排查

以下是部署过程中实际遇到并解决的问题，供参考。

1. 不要用 CentOS Stream 10

现象：dnf install -y mongodb-org 报 No match for argument，dnf install -y redis 同样找不到。

原因：CentOS Stream 10 太新，$releasever 解析为 10，MongoDB 和 Redis 官方仓库均未提供 10 的包。

解决：重装系统为 CentOS Stream 9，所有包正常安装。

2. SSH 连接报 REMOTE HOST IDENTIFICATION HAS CHANGED

现象：ssh -L 5000:... 报 WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!，无法连接。

原因：重装 VPS 系统后服务器 SSH 指纹变了，本地 known_hosts 里存的是旧指纹。

3. 浏览器访问报 Client sent an HTTP request to an HTTPS server

现象：用 http://localhost:5000 访问报错。

原因：Nemo Server 默认开启 HTTPS（自带自签名证书）。

解决：用 https://localhost:5000 访问，浏览器提示证书不安全时点”高级”→”继续前往”。

4. 登录面板失败（用户名密码正确但无法登录）

现象：输入默认账号密码 nemo/nemo 无法登录。

原因：裸机安装时 MongoDB 不会自动初始化数据，数据库里没有默认用户和工作空间。

现象：Worker systemd 服务启动后立刻退出，日志显示找不到配置文件，但文件确实存在。

原因：Worker 的 -f 参数读取配置文件时有路径 bug，报错路径缺少开头的 /。

6. Worker 配置中 redis.port 是 16379 而不是 6379

现象：worker.yml 里 redis 端口填 16379，不是 Redis 实际监听的 6379。

原因：这是 Nemo 的架构设计。Worker 不直接连 Server 的 Redis（6379），而是通过 Redis 安全隧道（Server 的 5002 端口）在本地 16379 建一个代理。Worker 连 16379 就是连这个本地代理，代理再转发到 Server 的 Redis。

结论：16379 是正确的，不要改成 6379。

7. 任务中 fofa 报 “没有可用的key”

现象：Worker 日志显示 fofa没有可用的key。

原因：没有配置 FOFA API Key，FOFA 在线查询被跳过。

解决：在 Nemo 面板 → 配置管理中填入 FOFA API Key。没有 Key 的话跳过即可，不影响其他任务。

8. 旧任务残留消息报 “task not exist”

现象：Worker 刚启动时日志刷一堆 Failed processing task xxx. Error = task not exist。

原因：之前 Worker 没启动时，Redis 队列里堆积了旧任务消息，但这些任务在 Server 端已经不存在了（超时或被清理）。

解决：残留消息被消费掉就完了，不影响新任务。面板上删掉旧任务，新建任务即可正常执行。

十二、常见问题

Q: 2G 内存够用吗？
A: MongoDB + Redis + Nemo Server + Worker 全部跑起来大概需要 1.2-1.5G。建议加 4G swap，Worker 并发设为 1，优先跑被动收集和指纹（-m 2,3）。详见第十节。

Q: 能用 CentOS Stream 10 吗？
A: 不能。MongoDB 和 Redis 官方仓库均未适配 CentOS Stream 10，必须用 CentOS Stream 9。详见踩坑记录第 1 条。

Q: Worker 任务卡在 CREATED 不执行？
A: 可能是消息队列消息丢失。在 Nemo 面板 -> 任务管理中删除卡住的子任务，重新执行。也可能是 Worker 没启动成功，检查 systemctl status nemo-worker。

Q: Chrome 截图失败？
A: 确保安装了 chromium 或 google-chrome。CentOS Stream 9 上用 dnf install -y chromium。

Q: nmap/masscan 权限不足？
A: 需要设置 SUID：sudo chmod u+s /usr/bin/nmap /usr/bin/masscan

Q: SSH 隧道断了怎么办？
A: 用 autossh 自动重连，或在 ssh 命令中加 -o ServerAliveInterval=60 保活。
